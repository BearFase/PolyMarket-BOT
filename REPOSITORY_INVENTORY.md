repository file through explicit paths or exhaustive directory/pattern groups.
Runtime files remain on disk and are intentionally excluded from Git.

## Dependency and data-flow findings

- Launchers call only `bot_launcher.py`; it starts `dashboard_server.py` using
  the same interpreter and project root.
- `dashboard_server.py` runs real-position sync, monitoring, the active
  canonical edge refresh, and the Flask app in `trader_dashboard.py`.
- Flask serves both dashboard HTML files, three JavaScript bundles, generated
  dashboard data, real positions, sports edges, system status, Game Flow, and
  post-game research APIs.
- Task Scheduler calls `.venv/Scripts/python.exe nfl_daily_update.py` with the
  repository as its working directory.
- The NFL workflow imports the canonical registry, operational safeguards,
  post-game research, simulation report, paper settlement engine, and Telegram
  center. It has no automatic paper-entry or real-order path.
- `dashboard_data.py` writes `dashboard_data.js`; real sync and the UI both use
  it. It is not a duplicate.
- Runtime reads/writes are project-relative through module `__file__` paths;
  manual and scheduled operations share the same production registry and
  atomic workflow checkpoint.
